# 커스텀 스펙 — 무한 커스텀의 범위와 설계 원칙

> 운동샵 예약·회원관리 SaaS의 핵심 차별화 "무한 커스텀" 정의 문서 (2026-07-27)
> 본 기획: [../README.md](../README.md) · 데이터 모델: [data-model.md](data-model.md)

## 설계 원칙

1. **커스텀 = 기능 스위치가 아니라 정책 값.** 설정 항목 100개 나열 금지. 회원권 상품 하나에 (유형 + 유효기간 + 홀딩 + 취소/노쇼 패널티 + 차감 규칙)이 묶이는 정책 번들 구조 — "10회권"을 만들면 규정이 따라온다.
2. **업종 프리셋으로 시작.** 필라테스 1인샵 / 에스테틱 등 프리셋 깔고 필요한 값만 수정. 무한 커스텀인데 첫 설정 5분.
3. **데이터 모델 도메인 중립.** Staff / Service / Membership / Booking / Resource + 용어 라벨 커스텀.

## 커스텀 영역 (사장이 바꾸고 싶어하는 것)

### 1. 회원권 정책 — 코어

| 항목 | 예시 |
|------|------|
| 유형 | 횟수제(10회), 기간제(3개월 무제한), 혼합(6개월 내 30회), 선불충전권(에스테틱) |
| 유효기간 기산 | 결제일부터 vs 첫 수업일부터 |
| 홀딩(일시정지) | 최대 N회, 총 N일 등 샵별 규정 |
| 차감 가중치 | 그룹 1회=1차감, 1:1=2차감 같은 교차 사용 |
| 사용 범위 | 회원권별 예약 가능 수업 제한 |
| 환불 계산식 | 사용분 정가 차감 후 환불 등 |

### 2. 예약/취소/노쇼 규칙

- 취소 마감선 (24h 전 / 당일 등)
- 마감선 넘긴 취소의 패널티 (차감 / 경고 / 없음)
- 노쇼 정의 + 누적 시 조치 (N회 → 예약 제한)
- 예약 오픈 시점, 최대 선예약 수, 대기자
- 정기 예약 (매주 화 10시 고정)
- 예약금 여부 (뷰티 버티컬)

### 3. 상품/서비스 정의

- 형태: 1:1 / 2:1(듀엣) / 그룹(정원 N)
- 서비스별 소요시간 (50분 수업 vs 90분 관리)
- 코스 구조 (에스테틱: 회차마다 다른 시술)

### 4. 스케줄/자원

- 강사별 요일 반복 가용시간 + 예외일/휴가
- 수업 간 버퍼 타임
- 베드/룸/기구 자원 제약 (뷰티, MVP 제외 — Resource 자리만 확보)
- 영업시간/휴무일

### 5. 회원 커스텀 필드

- 부상 이력, 상담 기록, 피부 타입, 선호 압, 메모, 회원 태그/등급

### 6. 용어/브랜딩

- 라벨: 선생님/강사/관리사/트레이너, 수업/시술/세션
- (후순위) 로고/색상

## LLM 설정 (자연어 → 정책 값) — 확정 방향, v2

조회에 이어 **설정도 LLM으로**: "우리는 당일 취소면 1회 차감이에요" → 정책 값 반영.

### 흐름

```
사장 자연어 입력
  → LLM이 구조화된 정책 diff 생성 (tool calling, 조회와 같은 패턴)
  → 변경 전/후 비교 UI로 확인 ("당일취소 패널티: 없음 → 1회 차감. 맞나요?")
  → 사장 확인 후에만 저장
```

### 가드레일

- LLM이 DB에 직접 쓰지 않는다. 항상 구조화된 diff + 사람 확인 단계를 거침 (조회는 read-only 함수, 설정은 confirm-required 함수)
- 해석 불확실하면 되묻기, 조용히 추측 반영 금지

### 배치

- MVP: LLM 조회만 (기존 3기능 유지)
- v2: LLM 설정 + 온보딩 활용 ("샵 규정을 말로 알려주세요" → 초기 설정 자동 구성) — "무한 커스텀인데 안 복잡함"의 완성. 파일럿 데모에서 강력한 한 방이 될 수 있음
