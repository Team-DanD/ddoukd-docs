# 서비스·강사 등록

상태: 기획 초안 · 2026-10-06. 기존 확정 정책과 이번 제안을 구분한다. API 구현 완료를 뜻하지 않는다.
화면: [서비스·강사 관리](../plans/service-staff/README.md).
근거: [데이터 모델](data-model.md), [권한](tenancy.md), [수업 생애주기](lifecycle.md).

## 누가 어디서 등록하는가

| 대상 | 담당 | 등록 경로 | 생성 결과 |
| --- | --- | --- | --- |
| 사업장·최초 사장 | 마스터 | 기존 백오피스 사업장 생성 | shop + OWNER staff |
| 서비스 | 사장 | 사업장 더보기 → 서비스 관리 → 서비스 등록 | 해당 shop의 service |
| 추가 강사 | 사장 | 사업장 더보기 → 강사 관리 → 강사 등록 | 로그인하지 않는 INSTRUCTOR staff |
| 강사 가용시간 | 사장 | 강사 관리 → 강사 상세 → 가용시간 설정 | 해당 staff의 요일별 시간 구간 |

최초 OWNER는 이미 강사로 선택할 수 있는 staff다. 1인샵에서 사장을 다시 등록하지 않는다. 마스터가 고객의 서비스를 대신 입력하거나 기본 서비스를 자동 생성하지 않는 흐름을 제안한다.

등록 진입 경로는 이번 제안이다. OWNER의 service·staff 생성 권한, 최초 OWNER 생성, 로그인 없는 staff는 기존 정책이다. **현재 INSTRUCTOR는 OWNER와 동일하게 동작한다**는 tenancy의 파일럿 정책을 유지한다. 따라서 지금 로그인 가능한 INSTRUCTOR가 있다면 동일 메뉴·API를 사용할 수 있다. OWNER만 접근 가능한 보안 경계라고 설명하면 안 된다. 다강사 로그인 도입 전에는 tenancy의 역할별 권한 분기를 별도 구현한다.

## 범위

서비스 등록·수정·비활성화·재활성화, 로그인 없는 강사 등록·정보 수정·비활성화·재활성화, 반복 가용시간, 개설/예약으로 돌아가는 흐름을 설계한다. 추가 강사 로그인 발급·초대·비밀번호 재발급, OWNER 추가·양도, 서비스별 강사 배정표, 휴가·특근 예외, 그룹 수업은 제외한다. 첫 슬라이스의 정원은 1이다.

`staff`는 강사와 계정을 합친 기존 엔터티다. 별도 강사 프로필 테이블을 만들지 않는다. 추가 강사는 `role=INSTRUCTOR`, `password_hash=null`, `email=null`, `active=true`로 생성한다. 이 화면에서 비밀번호를 입력하거나 발급하지 않는다.

## 첫 사용 순서

1. 마스터가 사업장과 최초 OWNER를 만든다.
2. 사장이 첫 로그인과 비밀번호 변경을 마친다.
3. 더보기에서 서비스를 등록한다. 강사 목록에는 사장 본인이 이미 보인다.
4. 본인 또는 추가 강사의 가용시간을 설정한다.
5. 수업 개설 또는 예약 추가로 진행한다.

새 온보딩을 강제로 띄우지는 않는다. 필요한 항목이 없으면 해당 작업 안에서 다음 행동을 안내한다.

## 서비스 입력

| 필드 | 초안 규칙 | 저장 |
| --- | --- | --- |
| 서비스명 | 필수, 앞뒤 공백 제거 후 1~50자 | name |
| 소요 시간 | 필수, 분 단위 정수 1~1440 | duration_minutes |
| 정원 | 읽기 전용 1명 | capacity=1 |
| 기본 차감 횟수 | 이번 화면에서 제외. 회원권 연결 전이며 저장 기본값 1 | deduction_count=1 |

이름 길이·시간 상한은 이번 제안이며 서버 DTO와 대조 후 확정한다. 소요 시간은 임의 기본값으로 저장하지 않는다. 화면의 50분은 예시 입력이다. 동일 이름을 금지하는 기존 제약이 없으므로 같은 이름만으로 저장을 막지 않으며 목록에 소요 시간을 함께 표시한다. 기술적 중복 제출은 제출 중 버튼 잠금으로 막는다.

수정된 소요 시간은 새 수업에만 적용한다. 기존 수업의 end_at·capacity는 바꾸지 않는다. 현재 모델은 이름을 join하므로 서비스명·강사명 수정은 과거 조회의 표시에도 반영된다. 수정 화면에서 이를 알린다. 과거 이름 고정이 필요하면 별도 스냅샷 설계가 필요하다.

## 강사 입력

| 필드 | 초안 규칙 | 저장 |
| --- | --- | --- |
| 이름 | 필수, 앞뒤 공백 제거 후 1~50자 | name |
| 공개 표시명 | 선택, 공백만 있으면 null, 최대 50자 | display_name |
| 연락처 | 필수, 하이픈·공백 제거 후 숫자 10~11자리 | phone |

이름 길이·전화번호 형식은 국내 파일럿 제안이다. 이메일·비밀번호·역할 선택은 받지 않는다. 같은 이름이나 전화번호만으로 별도 사람 등록을 차단하지 않는다. 공개 미리보기는 `display_name ?? name`을 그대로 보여주고, 비우면 실명이 공개됨을 입력 직전에 안내한다. 연락처는 공개 캘린더에 내보내지 않는다.

강사 등록 성공 후 상세로 이동하며 “가용시간 설정”을 주 행동으로 제시한다. 취소해도 등록된 강사는 유지되고 목록에 “가용시간 미설정”을 표시한다. 최초 OWNER의 연락처 등 누락 정보는 수정 화면에서 보완한다. OWNER를 다시 생성하거나 역할을 바꾸지 않는다.

## 가용시간: 개설까지 이어지는 제안

기존 모델은 요일 반복 가용시간을 수업 개설의 제안·검증 기준으로 정했지만, 미설정·범위 밖의 동작은 미정이다. 이 초안은 **가용시간을 먼저 저장하고 그 안에서만 개설**하는 안을 제안한다. 확정 전 구현하지 않는다.

- 월~일 중 근무 요일과 시작·종료를 입력한다. 요일당 여러 구간을 허용하고 “시간 추가”·구간 삭제를 제공한다. 미선택 요일은 근무 없음이다.
- shop.timezone 기준, 분 단위. 시작 < 종료, 같은 요일 구간 겹침 금지. 자정을 넘는 근무는 두 요일로 나눈다. 24:00 경계 입력의 서버 변환은 구현 시 확인한다.
- 전체 미설정 저장은 허용하되 수업 개설 가능 상태로 보지 않는다. 빈 가용시간이 종일 근무를 뜻하지 않는다.
- 새 수업의 시작부터 종료까지 하나의 가용 구간 안에 있어야 한다. 강사 수업 겹침 검사는 별도로 수행한다. 자정을 넘는 근무를 두 요일로 나누면 자정을 넘는 수업은 연속 근무여도 이 규칙에 걸린다. 그런 수업을 제외할지, 인접 구간을 이어서 판단할지는 확정 전에 정한다.
- 가용시간을 수정해도 이미 만든 수업·예약을 이동·취소하지 않는다. 이 영향은 저장 전에 안내한다.
- 등록과 가용시간 저장은 별도 단계다. 가용시간 실패 시 강사를 다시 생성하지 않고 해당 단계만 재시도한다.

## 수업 개설·예약 추가에서 연결

| 출발점 | 조건 | 안내와 행동 |
| --- | --- | --- |
| 수업 개설 C-02 / 즉석 예약 R-02 | 활성 서비스 없음 | 서비스 선택 대신 “등록된 서비스가 없어요” + 서비스 등록 |
| 두 폼의 서비스 선택 | 후보는 있으나 원하는 서비스 없음 | “새 서비스 등록” 보조 행동 |
| 두 폼의 강사 선택 | 활성 강사 없음 / 원하는 강사 없음 | 강사 등록. 정상 초기 사업장은 OWNER가 있어 빈 목록이 아님 |
| 강사 선택 후 | 가용시간 없음 | “가용시간을 먼저 설정해주세요” + 가용시간 설정 |
| 두 폼 | 필수 항목 미완성 | 제출 비활성 + 누락 사유. 다른 필드 입력은 유지 |
| 기존 수업 상세 C-03 → 예약 | 이미 개설된 세션 | service·staff를 다시 등록·선택하지 않고 기존 세션에 예약 |

등록 진입 시 폼의 날짜·시간·회원·공개 여부·선택 ID와 내부 복귀 지점을 같은 탭의 임시 상태로 보관한다. 임의 외부 return URL은 사용하지 않는다. 다른 샵·로그아웃·작업 완료에서는 임시 상태를 지운다. 새로고침 이후 복구는 이번 범위 밖이며 영구 저장으로 오해시키지 않는다.

서비스 저장 성공: 돌아가서 새 서비스를 선택하고 종료 시각을 다시 계산한다. 강사 저장 성공: 상세의 가용시간 저장까지 마친 뒤 돌아가 새 강사를 선택하고 가능 시각을 재검증한다. 가용시간 없이 돌아오면 강사는 선택하되 제출은 막고 설정 경로를 남긴다. 등록을 그만두면 원래 폼으로 돌아가고 새 항목은 선택하지 않는다. 원래 폼으로 돌아오는 것만으로 수업이나 예약을 자동 제출하지 않는다.

일반 관리 경로에서 저장한 경우 서비스는 목록, 강사는 상세로 이동한다. 취소로 서버에 저장된 항목을 롤백하지 않는다. 즉석 예약은 기존 정책대로 비공개 세션과 예약을 만들며, 등록 화면이 회원권 차감을 수행하지 않는다.

## 비활성·재활성 초안

`active=true ↔ false`. 물리 삭제는 제공하지 않는다. 비활성 항목은 관리 목록의 “비활성” 필터에서 조회·수정·재활성화하고 신규 수업의 후보에서 제외한다.

안전한 초기안으로, `end_at > 현재`이고 CANCELLED가 아닌 수업(진행 중 포함)이 하나라도 해당 항목을 참조하면 비활성화를 막는다. 예약 0건인 수업도 포함한다. 해당 수업 목록으로 안내하며 자동 휴강하지 않는다. OWNER 비활성화는 이 화면에서 제공하지 않는다(로그인 상실 방지). 과거 수업·예약은 join할 수 있게 그대로 둔다.

확인창에는 대상 이름, 신규 선택에서 제외됨, 이력 보존을 표시한다. 최종 서버 검사와 비활성 저장은 신규 수업 생성과 경쟁해도 불변 조건을 지켜야 한다. 프론트의 선조회만으로 보장하지 않는다. 재활성화는 보존된 가용시간을 복구해 사용하되 자동 수업 생성은 하지 않는다.

## 공통 저장·오류·권한 계약

- 요청의 shop_id를 신뢰하지 않는다. URL shop-key와 인증 토큰을 매번 대조하고 모든 조회·수정·선택 ID를 같은 shop으로 제한한다. 다른 샵 리소스는 노출하지 않는다.
- 미인증은 로그인, 임시 비밀번호 상태는 비밀번호 변경으로 보낸다. 재인증 뒤 자동 제출하지 않는다.
- 최초 로딩 실패는 빈 목록으로 표시하지 않는다. 오류와 재시도를 제공한다. 필드 오류는 해당 필드 아래 표시하고 첫 오류로 포커스를 이동한다.
- 저장 중 중복 클릭을 막는다. 저장 실패 시 값 유지·버튼 복구·재시도. 응답 유실 시 저장 여부를 확인한 뒤 재시도하며 생성 API의 중복 방지 방식은 구현 전 합의한다.
- 타 관리자의 비활성화·가용시간 변경은 최종 수업 제출 시 재검증하고 잘못된 선택을 해제하거나 시간 재선택을 요구한다. 다른 입력은 보존한다.
- 이 문서는 동작 계약이다. 엔드포인트 경로·오류 코드·기존 서버 지원 여부는 확인하지 않았으므로 구현된 API처럼 제시하지 않는다.

## 검증 시나리오

1. 신규 shop 로그인 → OWNER 1명 확인 → 서비스 등록 → OWNER 가용시간 저장 → 수업 개설 가능.
2. R-02에서 회원·날짜 입력 → 서비스 등록 → 복귀 시 값 보존·서비스 자동 선택 → 명시적 제출 전 예약 없음.
3. 강사 등록 → 가용시간 저장 실패 → 강사 중복 생성 없이 시간만 재시도.
4. 표시명 공란/입력 각각의 공개 미리보기 확인. 전화번호는 공개 응답에 없음.
5. 서비스 시간 수정 후 과거·미래 기존 세션의 종료 시각·정원 불변.
6. 다른 샵 ID 접근 차단, 현재 파일럿 INSTRUCTOR 동등 권한, 향후 권한 분기와 구분.
7. 활성 목록 0건·검색 0건·조회 실패를 구분. 비활성만 있는 경우 관리 필터로 복구 가능.
8. 진행 중/미래 수업이 있는 항목 비활성 차단. 마지막 OWNER 비활성 불가. 이력만 있는 항목은 비활성 후 이력 조회 가능.
9. 가용시간 미설정·구간 겹침·소요 시간으로 종료가 범위를 벗어나는 경우 개설 차단. 기존 세션에 예약 추가 시 시간 재설정 요구 없음.

## 확정할 항목

| 항목 | 이 초안의 제안 | 영향 |
| --- | --- | --- |
| 가용시간 없는 강사·범위 밖 개설 | 먼저 설정, 범위 밖 차단 | C-02·R-02·기존 서버 검증 |
| 비활성화의 기존 수업 처리 | 진행 중/미래 수업 있으면 차단 | staff·service 변경 API |
| 추가 강사 로그인 | 이번 범위에서 발급 안 함 | 다강사 권한 분기와 함께 후속 기획 |
| 입력 제한 | 이름 50자, 시간 1~1440분, 국내 전화 10~11자리 | 서버 DTO 대조 필요 |
| 하단 메뉴 | 더보기 아래 관리 메뉴 추가 | 전체 내비게이션 순서는 기존 미결 유지 |

이번 요청으로 기획 초안을 작성했으며 위 신규 정책을 사용자 확정 결정으로 기록하지 않는다.
