# 검증 시나리오

[README.md](README.md)의 진행 순서에서 쓰는 시나리오다. 화면 번호는 기획 문서의 번호다.

- `S-` 화면: [plans/backoffice-staff-auth/README.md](../backoffice-staff-auth/README.md) (사업장 인증)
- `M-`, `R-` 화면: `plans/member-booking/README.md` (회원 · 예약. PR #16이 머지되면 저장소에 들어온다)

화면을 똑같이 만드는 것이 목적이 아니다. **흐름이 끊기지 않는지**와 아래 "확인할 것"을 본다.

## 가짜 데이터

실제 서버 없이 고정된 응답으로 돈다. 아래는 가짜 데이터용 가정이며 제품 결정이 아니다.

| 항목 | 값 |
| --- | --- |
| 샵 | 두 개. `maymi-pilates`(Asia/Seoul), `second-shop`(다른 샵 격리 확인용) |
| 비활성 샵 | `closed-shop` 하나 (없는 샵과 같은 화면이 나와야 한다) |
| 사업장 user | 샵마다 한 명. 한 명은 임시 비밀번호 상태(`must_change_password`) |
| 회원 | 30명 이상. 성이 같은 회원 여러 명, 이름이 긴 회원 한 명, 전화번호가 겹치는 등록 시도 한 건 |
| 강사 · 서비스 | 강사 2명, 서비스 1개("1:1 개인레슨 50분", 정원 1) |
| 예약 | 하루에 `BOOKED`(시작 전, 진행 중, 종료 후), `CANCELLED`, `NO_SHOW`가 모두 있게 |
| 실패 응답 | 로그인 실패, 전화번호 중복, 예약 409(강사 시간 겹침), 목록 조회 실패 |
| 응답 지연 | 일부 요청에 1~2초. 중복 제출과 진행 표시를 보기 위해 |

그룹 수업, 회원권, 대기는 넣지 않는다(슬라이스 1 범위 밖).

## B. 회원 선택

| 항목 | 내용 |
| --- | --- |
| 화면 | R-02 예약 추가 → R-02s 회원 선택 시트 → R-02 |
| 흐름 | 회원 필드를 누른다 → 시트가 열린다 → 한글로 검색한다 → 회원을 고른다 → 시트가 닫히고 값이 채워진다 |
| 확인할 것 | 한글 조합 중(예: "김" 입력 도중)에 검색이 어긋나지 않는가 |
| | 시트가 열릴 때 포커스가 검색 필드로 가고, 닫히면 회원 필드로 돌아오는가 |

| | 뒤로 가기(Android 버튼, 브라우저 뒤로)가 시트만 닫는가 |
| | 결과가 없을 때와 불러오기에 실패했을 때의 표시 |
| | 시트를 닫아도 폼의 다른 입력 값이 남아 있는가 |
| 근거 | components-operator.md Modal · Select("수가 많고 검색이 필요한 대상은 선택 시트") |

## C. 예약 입력

| 항목 | 내용 |
| --- | --- |
| 화면 | R-02 예약 추가 |
| 흐름 | 강사, 서비스, 날짜, 시작 시각을 고른다 → 종료 시각이 계산돼 보인다 |
| 확인할 것 | 폰에서 날짜와 시각이 OS 선택기로 열리는가. 웹에서는 무엇으로 열리는가 |
| | 기기의 타임존을 샵과 다르게 바꿨을 때도 날짜와 시각이 샵의 타임존으로 보이는가 |
| | 종료 시각이 서비스의 소요 시간으로 계산돼 읽기 전용으로 보이는가 |
| | 입력 글자가 16px이라 iOS에서 화면이 확대되지 않는가 |
| | Select가 폰에서 네이티브 선택기로 열리는가 |
| 가정 | 시각 입력 단위(30분), 강사 가용시간 밖 시각의 처리는 정해지지 않았다. 가짜 데이터에서는 30분 단위에 제한 없음으로 둔다 |
| 근거 | data-model.md service · class_session, components-operator.md DatePicker · TimePicker |

## D. 예약 결과

| 항목 | 내용 |
| --- | --- |
| 화면 | 성공 → R-01 예약, 실패 → R-02e |
| 흐름 | 예약 버튼을 누른다 → (지연) → 성공이면 예약 목록에 새 행이 보이고 알림이 뜬다 / 실패면 폼 위에 오류 요약이 뜬다 |
| 확인할 것 | 버튼을 빠르게 두 번 눌러도 요청이 한 번만 나가는가 |
| | 진행 중에 버튼 폭이 유지되고 진행 중이라는 것이 읽히는가 |
| | 실패했을 때 입력 값이 전부 남아 있고, 고쳐서 다시 낼 수 있는가 |
| | 오류 요약이 사라지지 않고 남아 있는가. 스크린리더에 읽히는가 |
| | 성공 뒤 예약 목록의 날짜가 방금 만든 예약의 날짜인가 |
| | 진행 중인 예약 행만 옅은 보라 면인가 |
| 가정 | 서버가 409의 원인(정원 마감, 닫힘, 지난 시각, 강사 겹침)을 구분해 주는지는 정해지지 않았다. 가짜 데이터는 강사 겹침 문구 하나를 내려준다 |
| 근거 | lifecycle.md 4절, components-operator.md Form("제출 실패" · "서버 오류 요약") |

## E. 예약 상세

| 항목 | 내용 |
| --- | --- |
| 화면 | R-01 → R-03 예약 상세 시트 → R-03n 노쇼 확인 |
| 흐름 | 예약 행을 누른다 → 상세 시트 → 노쇼 기록 → 확인 시트 → 기록 → 목록의 배지가 바뀐다 |
| 확인할 것 | 시트에서 시트로 넘어갈 때 포커스와 뒤로 가기가 어긋나지 않는가 |
| | 확인 시트는 배경을 눌러도 닫히지 않는가. 처음 포커스가 그만두기에 있는가 |
| | `CANCELLED`와 `NO_SHOW` 예약의 상세에는 취소·노쇼 버튼이 없는가 |
| | 종료 시각이 지난 `BOOKED` 예약이 "완료"로 보이는가(저장된 상태가 아니라 화면의 표시) |

| 가정 | 취소와 노쇼를 언제부터 언제까지 허용할지는 정해지지 않았다. 가짜 데이터에서는 `BOOKED`면 항상 둘 다 보여준다 |
| 근거 | lifecycle.md 2절·3절, plans/member-booking "예약 상태별 표시와 행동" |

## F. 경로와 테넌트 경계

실제 호스팅에 올려서 본다(진행 순서 3번).

| 항목 | 내용 |
| --- | --- |
| 화면 | S-01, R-01, 공개 캘린더 경로(`/{shop-key}/schedule`) |
| 확인할 것 | 새 shop-key를 가짜 데이터에 추가했을 때 다시 배포하지 않고 그 경로로 들어갈 수 있는가 |
| | 깊은 경로(`/{shop-key}/...`)에서 새로고침해도 404가 나지 않는가 |
| | 샵 A에 로그인한 채 샵 B의 경로를 치면 샵 A의 화면이나 데이터가 보이지 않는가 |
| | 토큰을 샵마다 따로 보관하는가(같은 오리진이라 저장소가 공유된다) |
| | 샵 A에서 로그아웃하면 샵 B의 로그인이 유지되는가(또는 의도대로 동작하는가) |
| | 공개 캘린더 경로는 로그인 없이 열리고, 운영자 내비게이션이나 로그인 정보가 없는가 |
| | 공개 캘린더에 나가는 항목이 수업명, 시작·종료 시각, 강사 표시명, 잔여 정원뿐인가 |
| 가정 | 다른 샵의 토큰으로 접근했을 때 보여줄 화면(403)과 세션 만료 시 동작은 정해지지 않았다. 로그인 화면으로 보내는 것으로 둔다 |
| 근거 | tenancy.md 3절·5절·7절 |

화면에서 확인한 것을 서버의 격리가 검증됐다고 적지 않는다. [README.md](README.md) "가짜 데이터로 확인할 수 없는 것" 참고.

## G. 상태 갤러리

화면 하나에 컴포넌트의 상태를 모아 디자인 조건을 본다(진행 순서 4번). 기준은 [디자인 시스템](../../design-system/README.md)과 `design-system/claude-design/project/components/`의 미리보기다.

| 확인할 것 | 조건 |
| --- | --- |
| 포커스 표시 | 키보드로 이동했을 때만 보라 2px outline. 오류 테두리 위에서도 보이는가. 앱에서는 VoiceOver · TalkBack 포커스도 본다 |
| 선과 모서리 | 1px 선이 기기 배율에서 뭉개지지 않는가. 모서리 8px · 4px |
| 누르는 영역 | 버튼 48px, 그 밖 44px 이상 |
| 글자 | Noto Sans KR 400 · 500 · 700이 실제로 그 굵기로 보이는가. 숫자의 자릿수가 맞는가(tabular-nums) |
| 좁은 화면 | 360px에서 행과 하단 바가 깨지지 않는가 |
| 긴 글 | 긴 회원 이름과 긴 오류 문구가 잘리지 않고 줄바꿈되는가 |
| 글자 확대 | OS의 글자 크기를 키웠을 때 |
| 시트 안 입력 | 시트 안의 필드에 입력할 때 키보드와 겹치지 않는가 |
| 움직임 줄이기 | 설정을 켰을 때 전환이 빠지는가 |
