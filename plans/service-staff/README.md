# 서비스·강사 관리

- 목적: 수업 개설·예약 추가의 선행 데이터인 서비스·강사·가용시간을 사장이 등록하고 원래 작업을 이어가게 한다.
- 상태: 초안, 2026-10-06. 아래 신규 정책은 확정 전 제안이다.
- 스펙: [서비스·강사 등록](../../spec/service-staff-registration.md). 필드·권한·예외·검증의 진실 원천이다.
- 화면 원본: [service-staff.pen](service-staff.pen). 디자인 시스템의 토큰 105개와 컴포넌트를 복사한 뒤 신규 화면 19개를 구성했다. 원본 디자인 시스템은 수정하지 않았다.
- 근거: [데이터 모델](../../spec/data-model.md), [테넌시](../../spec/tenancy.md), [운영자 컴포넌트](../../design-system/components-operator.md).

## 핵심 흐름

마스터가 최초 OWNER 생성 → 사장이 더보기에서 서비스 등록 → 기존 OWNER 또는 추가 강사의 가용시간 설정 → 수업 개설/예약 추가.

- 최초 사장도 staff이므로 강사로 다시 등록하지 않는다.
- 추가 강사는 로그인 없는 staff로 등록한다. 이메일·비밀번호·계정 초대는 이번 범위 밖이다.
- 등록 중인 C-02(수업 개설)·R-02(즉석 예약)에서 진입하면 저장 후 새 항목을 선택하고 기존 입력을 보존한다. 자동으로 수업·예약을 제출하지 않는다.
- 현재 파일럿 INSTRUCTOR는 OWNER와 동등 권한이다. 사장 중심 업무 흐름과 실제 접근 제한을 혼동하지 않는다.

| SV-01i | 서비스 관리 · 비활성 | 비활성 탭, 항목 1개 예시 | 다시 활성화 후 활성 목록 |

ST-03은 추가 강사의 등록 완료 예시다. 기존 강사 진입에는 완료 문구를 숨기고, OWNER에는 비활성화 버튼을 숨긴다. 원래 폼으로 돌아가기는 그 폼에서 진입했을 때만 보인다. ST-04의 복귀 안내도 같은 조건이다. 가용시간이 이미 있으면 ST-03에 요약과 “가용시간 수정”을 표시한다. ST-05에서 OWNER 역할·계정 정보는 바꾸지 않는다.

ST-04의 시간 추가는 요일을 선택한 뒤 ST-04t를 연다. 각 요일의 +는 해당 요일의 새 구간, 시간은 편집, −는 구간 삭제다. 여러 구간이면 요일 아래에 행을 늘리고 본문을 스크롤한다. ST-04t의 뒤로는 그 구간의 미적용 변경을 버린다. ST-04에서 저장하지 않은 변경을 두고 나가면 이탈 확인을 띄운다. 구간 겹침·시작≥종료는 입력 아래 오류로 표시한다.

SV-01i는 비활성 항목 1개를 선택한 예시다. 여러 항목이면 행 선택 후 해당 항목의 활성화 확인을 제공한다. 강사 비활성 탭·재활성화도 이 패턴을 사용한다. 활성/비활성은 실제 버튼 탭이며, 검색 결과 0건과 조회 실패는 스펙의 상태 구분을 따른다.

`.pen`은 정적인 화면 명세다. 실행 가능한 웹 앱이나 실제 클릭 프로토타입으로 검증하지 않았다. 화면 간 이동 계약은 위 표와 스펙에 기록했다. 새 LK 화면은 기존 C/R 화면을 대체하지 않는 연결 상태 예시다.

## 기존 기획과 통합할 부분

현재 main에는 수업·회원예약 기획이 아직 없다. 별도 수업 기획의 README를 읽고 C-02, C-03, R-02 번호와 의존성을 확인했다. 그 작업 공간의 문서·pen은 수정하지 않았다.

- 수업 기획의 “서비스·강사 등록 경로 없음”과 미결 1은 이 문서로 연결한다.
- C-02·R-02의 서비스·강사 선택에 “새로 등록” 진입점을 추가한다. 활성 후보가 없으면 LK-01 패턴을 쓴다.
- R-02도 가용시간 미설정일 때 LK-03 패턴을 쓴다. 기존 수업에 예약하는 C-03 경로는 서비스·강사를 다시 입력하지 않는다.
- 기존 기획 합류 후 실제 C/R 원본에 연결 상태를 통합해야 한다. 이 초안이 다른 작업 공간의 원본을 갱신한 것으로 해석하지 않는다.

## 신규 정책과 미결

1. 가용시간 미설정·범위 밖 개설을 막는 안. 기존에는 미정이었다.
2. 진행 중·미래 수업이 있으면 비활성화를 막는 안. 자동 휴강은 하지 않는다.
3. 서비스 자동 생성 없이 사장이 직접 등록하는 안.
4. 입력 길이·전화번호·시간 상한은 서버 DTO 대조 후 확정한다.
5. 전체 하단 내비게이션 순서는 기존 미결이다. G-01은 예약/회원/수업/더보기 후보를 보여준다.

이 초안 때문에 다강사 권한 분기나 추가 로그인 계정 발급이 구현된 것으로 간주하지 않는다.

## 검증

- pencil MCP로 작성·조회했으며 `.pen` 내용을 텍스트로 열거나 편집하지 않았다.
- 재사용 버튼·입력·상단 바·탭·하단 내비게이션과 기존 역할 색·글꼴 토큰을 사용했다.
- 화면 스크린샷으로 폼, 오류, 복귀, 가용시간, 비활성화 상태를 확인했다. 전체 신규 프레임 구조 검사에서 잘림 보고가 없었다.
- 정책·권한·동시성 검증 항목은 스펙의 검증 시나리오에 있다. 서버·프론트 코드는 수정하거나 실행하지 않았다.
